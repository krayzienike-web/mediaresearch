# ADR 0001. Минимизация персональных данных

**Статус:** принято · **Дата:** 2026-10-23

## Контекст

Посты и комментарии пользователей соцсетей — персональные данные по 152-ФЗ, даже если
профиль открытый. Ссылка на пост ВК (`vk.com/wall<id>_<post>`) содержит ID пользователя,
поэтому «ссылка + текст» остаются персональными данными, даже без имён.
Полностью выйти из-под 152-ФЗ, сохраняя ссылки, нельзя. Можно минимизировать объём и риски.

## Решение

| Данные | Хранение |
|---|---|
| Публикации СМИ, Telegram-каналов, сообществ ВК | Полностью: это не ПДн физлиц |
| Имя, аватар, профиль пользователя | Не сохраняем никогда. Профили из ответа API отбрасываются в сборщике |
| ID пользователя | Только HMAC-SHA256 с секретной солью (`AUTHOR_HASH_SALT`): можно считать уникальных авторов, нельзя узнать ID |
| Текст поста пользователя | Хранится `USER_TEXT_RETENTION_DAYS` (90) дней, потом стирается командой `mr purge` |
| Ссылка и метрики поста пользователя | Хранятся: нужны для работы PR-службы |
| Документы без упоминаний брендов | Не сохраняются |

Только официальные API и открытые веб-превью. HTML ВК не парсим.

## Последствия

- Перед запуском в работу: юрист компании добавляет цель «мониторинг публичных упоминаний»
  в уведомление РКН и утверждает срок хранения. Данные хранятся на серверах в РФ.
- `mr purge` должен запускаться регулярно (cron) в рабочей установке.
- Потерять соль = потерять связность авторов. Сменить соль = то же самое.
