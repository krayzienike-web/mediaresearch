# ADR 0003. Тональность

**Статус:** принято · **Дата:** 2026-10-23

## Контекст

PR-службе нужна тональность каждого упоминания, в первую очередь — быстро видеть негатив.
Бюджет нулевой, видеокарты нет, данные не должны уходить во внешние сервисы.

## Решение

- **Локальная модель** `cointegrated/rubert-tiny-sentiment-balanced`: ~50 МБ, CPU, три класса
  (негатив, нейтрально, позитив). Меняется через `SENTIMENT_MODEL` в `.env`.
  Внешние LLM-API не используем: стоимость и передача текстов третьим лицам.
- **Оценивается фрагмент, а не весь текст**: только предложения, где сработали правила бренда.
  В новости «Конкурент провалился, а Сбербанк показал рост» упоминание Сбера — не негатив.
- **Тональность хранится у упоминания, а не у документа**: один текст может быть позитивным
  для одного бренда и негативным для другого.
- **Ручная правка главнее модели**: `sentiment_manual = true`, модель её не перезаписывает.
  Ручные правки и пометки «мусор» — будущий датасет для дообучения.
- Оценка — отдельный шаг после сбора (`mr sentiment`, автоматически в `mr collect`),
  чтобы сбор работал и без установленной модели.

## Последствия

- Модель обучена на отзывах и соцсетях; на новостях СМИ она будет чаще ставить «нейтрально»
  и может ошибаться на сарказме. Точность замерим на ручной разметке (этап 1).
- Если точности не хватит: дообучение на наших правках или модель покрупнее (rubert-base).
- PyTorch из PyPI на Linux тянет CUDA (~3 ГБ). Для сервера соберём Docker-образ с CPU-версией.
