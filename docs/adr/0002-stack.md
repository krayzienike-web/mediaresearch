# ADR 0002. Стек

**Статус:** принято · **Дата:** 2026-10-23

## Контекст

Внутренний сервис, одна компания, ~20 брендов, разработчик один. Ожидаемый объём —
от сотен до нескольких тысяч упоминаний в день. Бюджет — как у пет-проекта.

## Решение

- **Python 3.12+**: лучшая экосистема NLP для русского (pymorphy3, Natasha, RuBERT).
- **PostgreSQL** — единственное хранилище. Полнотекстовый поиск (`russian`) и `pg_trgm`
  при необходимости. OpenSearch отложен: дорог по памяти и администрированию на таком объёме.
- **SQLAlchemy 2 + Alembic**. Миграции подключены вместе с ручной разметкой (её нельзя терять
  при изменении схемы). `mr init-db` применяет миграции; базу без миграций помечает начальной.
- **Без брокера очередей**: сбор по расписанию в одном процессе (`mr collect --every N`).
  Если упрёмся — очередь на Postgres (procrastinate), потом Redis.
- **CLI (Typer)** для сбора и обслуживания.
- **Веб: FastAPI + Jinja2 + htmx**, оформление Pico CSS, графики Chart.js. HTML собирается
  на сервере, без отдельного фронтенд-проекта и сборки JS. Библиотеки лежат в
  `web/static/vendor`, интерфейс работает без доступа к CDN.
- **Docker Compose** для инфраструктуры, VPS в РФ для работы.

## Когда пересматривать

- Поиск по базе медленный или нужна сложная поисковая логика → OpenSearch.
- Сбор не укладывается в интервал → параллельные воркеры и очередь.
- Аналитика по миллионам строк тормозит → ClickHouse.
